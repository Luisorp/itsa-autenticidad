01 · Propósito y alcance

Este informe verifica funciones del Sistema de autenticidad mediante casos reproducibles. Sigue el formato del ejemplo proporcionado: título, prioridad, precondición, descripción, datos, pasos y resultado esperado. Se incorporan resultado obtenido, estado y evidencia para distinguir lo diseñado de lo ejecutado.

Se documentan 18 casos, superando el mínimo de 10 solicitado. El alcance comprende acceso, usuarios, permisos, estudiantes, carga de PDF, comparación, reportes, respaldos y adaptación móvil.

Criterio de aprobación

Un caso se aprueba cuando las comprobaciones automatizadas confirman el resultado esperado. La captura documenta el estado visible; la verificación de campos, archivos o registros complementa la imagen. Las pruebas negativas se aprueban cuando el sistema rechaza correctamente una entrada inválida.

Tratamiento de las evidencias

Las capturas proceden de la aplicación real con datos sintéticos. Para usar la denominación solicitada, el rótulo de marca se sustituyó visualmente por “Sistema de autenticidad” solo en el navegador de pruebas. Los mensajes de validación y resultados se conservaron.

Los formularios se operaron mediante automatización. TC-014 envía una combinación incompatible directamente al servidor. Los selectores de autocompletado no se consideran exhaustivamente probados. No se editaron los archivos funcionales del proyecto.

Reglas verificadas en el código

Las cuentas se crean desde administración; no hay registro público. Los roles actuales son administrador, gestor y usuario. Proyectos admite PDF hasta 30 720 KB. La comparación manual exige la misma modalidad y contenido analizable.

05 · Implantación local

La implantación prepara una computadora para ejecutar el código, conectar MySQL y conservar los documentos. Esta sección describe el procedimiento; no registra una reinstalación de la base principal durante este informe.

EntornoWindows y Laragon; PHP 8.3 compatible con composer.json; Composer; Node.js y npm compatibles con package.json.
Servidor y baseServidor web y MySQL activos. La raíz web debe apuntar a public.
CódigoUsar la versión acordada; conservar composer.lock y package-lock.json.
ConfiguraciónPreparar .env con DB_CONNECTION=mysql, conexión local correcta y APP_URL. En un traslado, conservar la APP_KEY existente.
DocumentosCopiar storage/app/public conservando rutas y recrear public/storage si falta.
Dependenciascomposer install
npm ci
Base de datosRespaldar antes de migrar. En una base vacía, ejecutar migraciones. Para trasladar registros, importar una copia MySQL compatible y revisar migraciones pendientes.
Recursos y cachénpm run build
php artisan optimize:clear
VerificaciónComprobar manifest.json, inicio de sesión, permisos, carga y apertura de PDF, comparación, reportes y respaldo.

SISTEMA DE AUTENTICIDAD

06 · Traslado y aceptación

Traslado a otra computadora

El código se obtiene del repositorio. MySQL se traslada mediante una exportación e importación compatibles: copiar database.sqlite no traslada MySQL. Los PDF se copian por separado conservando sus rutas. La configuración del destino debe adaptarse sin divulgar credenciales.

Respaldo y recuperación

El respaldo del sistema exporta registros de nueve tablas del negocio. Requiere un destino con el mismo esquema. Incluye instrucciones que reemplazan datos; su restauración debe ensayarse primero en una base separada.

Copia completaExportación MySQL, storage/app/public, configuración protegida y referencia del commit.
Antes del cambioDetener escrituras, comprobar las copias y registrar conteos por tabla y archivos.
Después del trasladoComprobar relaciones, permisos, apertura documental, resultados y descargas.
AceptaciónCasos críticos aprobados en el destino y ausencia de incidencias que impidan el flujo de trabajo.
ReversiónRecuperar conjuntamente código, base y documentos anteriores desde respaldos verificados.

Comandos de comprobación

php artisan migrate:status
php artisan route:list --except-vendor
npm run build
php artisan storage:link

El último comando solo se necesita si falta el enlace de almacenamiento. No regenerar la clave de una instalación trasladada ni vaciar la base para resolver errores de configuración.

Observaciones

Idioma: algunos errores de credenciales y formularios se muestran en inglés. Conviene unificar las traducciones para usuarios hispanohablantes.

Motor de datos: se utilizó SQLite aislado. La configuración de uso es MySQL; la compatibilidad y el respaldo en ese motor requieren comprobación propia.

Documentos: los archivos de prueba tienen texto extraíble. No se evaluó OCR ni PDF escaneados. El respaldo SQL no incluye los archivos binarios.

Alcance: estos casos no sustituyen una auditoría de seguridad, pruebas de carga ni una evaluación estadística del algoritmo.
